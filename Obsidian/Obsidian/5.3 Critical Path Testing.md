## **Critical Path Testing (Тестирование критического пути)**

### **Что такое Critical Path Testing?**

Critical Path Testing (Тестирование критического пути) — это метод тестирования, который фокусируется на **основных (критических) бизнес-процессах** приложения. Он направлен на тестирование тех функциональностей, без которых система **не может выполнять свои ключевые задачи**.

> 🎯 **Критический путь** — это последовательность шагов, необходимых для успешного завершения важного процесса.  
> Если хотя бы один из этих шагов не работает, то весь процесс терпит неудачу.

---

## **Когда используется Critical Path Testing?**

- Для **проверки ключевых пользовательских сценариев** (например, покупка в интернет-магазине).
- При **ограниченном времени на тестирование**, когда важно сфокусироваться на самом главном.
- В **миссион-критичных системах** (банкинг, медицина, авиация), где ошибки могут привести к серьезным последствиям.
- В **автоматизированном тестировании**, чтобы создавать тесты, которые покрывают самые важные бизнес-функции.

---

## **Как проводится Critical Path Testing?**

1️⃣ **Определение критического пути**

- Анализируются бизнес-процессы.
- Выявляются обязательные шаги, без которых функциональность не работает.

2️⃣ **Разработка тест-кейсов**

- Создаются сценарии, которые проверяют критические шаги.
- Покрываются **как позитивные, так и негативные случаи**.

3️⃣ **Запуск тестов**

- Тесты выполняются вручную или автоматически.
- Анализируются результаты.

4️⃣ **Оптимизация и поддержка тестов**

- При изменениях в бизнес-логике тесты обновляются.

---

## **Пример Critical Path Testing**

### **Приложение: Интернет-магазин**

📌 **Критический путь: Оформление заказа**

1. Пользователь открывает сайт. ✅
2. Выбирает товар и добавляет в корзину. ✅
3. Переходит в корзину и нажимает "Оформить заказ". ✅
4. Вводит данные доставки и оплаты. ✅
5. Подтверждает заказ. ✅
6. Получает сообщение об успешном оформлении. ✅

Если **любой из этих шагов не выполняется**, то бизнес-процесс нарушается, и пользователи не могут завершить покупку.

---

## **Critical Path Testing vs. Smoke Testing**

Эти два вида тестирования имеют схожие цели, но есть отличия:

|**Критерий**|**Critical Path Testing**|**Smoke Testing**|
|---|---|---|
|**Цель**|Проверка ключевых пользовательских сценариев|Проверка базовой работоспособности системы|
|**Фокус**|Основные бизнес-процессы|Минимально необходимая работоспособность|
|**Глубина проверки**|Глубже, тестируются все шаги критического пути|Поверхностное тестирование|
|**Когда выполняется?**|Когда нужно проверить ключевые функции|После каждого билда|

---

## **Заключение**

Critical Path Testing помогает **гарантировать, что самые важные бизнес-функции работают корректно**. Это особенно важно для систем, где сбои могут привести к серьезным последствиям (например, финансовые транзакции или медицинские системы).

🚀 **Если критический путь сломан – приложение не выполняет свою основную задачу!**
