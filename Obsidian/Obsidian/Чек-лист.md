**Чек-лист в QA (Quality Assurance)** — это документ, содержащий список проверок, которые необходимо выполнить для проверки качества программного продукта. Чек-лист помогает тестировщикам убедиться, что все ключевые аспекты приложения протестированы, и ни один из важных шагов не был пропущен.

### **Цели чек-листа в QA:**

1. **Стандартизация тестирования** — обеспечивает единый подход для всех тестировщиков.
2. **Контроль качества** — помогает выявлять дефекты на ранних этапах.
3. **Снижение человеческого фактора** — минимизирует вероятность пропуска важных проверок.
4. **Упрощение процесса тестирования** — облегчает планирование и выполнение тестов.

### **Что включается в чек-лист:**

1. **Функциональные проверки:**
    - Работоспособность основных функций.
    - Корректность расчетов.
    - Проверка валидации данных.
2. **UI/UX тестирование:**
    - Проверка интерфейса на соответствие макетам.
    - Удобство использования (юзабилити).
    - Корректное отображение на разных устройствах и разрешениях.
3. **Тестирование безопасности:**
    - Проверка на SQL-инъекции.
    - Защита личных данных пользователей.
4. **Кросс-браузерное тестирование:**
    - Проверка работы в разных браузерах (Chrome, Firefox, Edge и т.д.).
5. **Производительность:**
    - Время загрузки страниц.
    - Нагрузка при высоком трафике.
6. **Совместимость:**
    - Работа на разных операционных системах и устройствах.
7. **Регрессионное тестирование:**
    - Проверка работы старых функций после внесения новых изменений.

### **Пример простого чеклиста для веб-приложения:**

1. Открывается ли главная страница?
2. Корректно ли работают ссылки на сайте?
3. Происходит ли успешная авторизация пользователя?
4. Сохраняются ли введённые данные после перезагрузки страницы?
5. Корректно ли отображаются элементы на мобильных устройствах?

Чеклисты часто используются для ручного тестирования и могут быть дополнены автоматизированными тестами для повышения эффективности проверки качества продукта.
