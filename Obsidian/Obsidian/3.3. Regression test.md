# **Regression Testing (Регрессионное тестирование)**

## **Что такое Regression Testing?**

Regression Testing (регрессионное тестирование) — это процесс повторного тестирования уже существующего функционала после внесения изменений в код (например, исправления багов, добавления новых функций, рефакторинга).

> 📌 **Цель:** Убедиться, что после внесения изменений **старая функциональность не сломалась**.

---

## **Когда проводится Regression Testing?**

✅ После исправления багов.  
✅ После добавления новых функций.  
✅ После обновления внешних библиотек или API.  
✅ После рефакторинга или оптимизации кода.  
✅ Перед каждым новым релизом.

---

## **Как проводится Regression Testing?**

### 1️⃣ **Определение тестируемых областей**

📌 Что важно протестировать?

- Функции, **связанные с измененным кодом**.
- **Критические бизнес-процессы** (например, оформление заказа в интернет-магазине).
- **Интеграции с другими модулями** и API.

🎯 **Пример:**  
Если в мобильном банке добавили **новый способ оплаты через QR-код**, нужно проверить:

- Работает ли **новая функция**.
- Работают ли **старые способы оплаты** (карта, переводы, Apple Pay).

---

### 2️⃣ **Выбор стратегии тестирования**

Есть три подхода:

1. **Полное регрессионное тестирование** — проверка всей системы (затратно).
2. **Частичное регрессионное тестирование** — проверка только затронутых областей.
3. **Выборочное тестирование** — запуск только наиболее критичных тестов.

🎯 **Пример:**  
Если разработчики изменили **логин через соцсети**, можно протестировать:

- Логин через Facebook и Google.
- Вход с паролем.
- Восстановление пароля.
- Личный кабинет (но не всю систему).

---

### 3️⃣ **Автоматизация Regression Testing**

📌 **Почему автоматизация важна?**

- Регрессионные тесты **запускаются часто** (при каждом изменении кода).
- Вручную проверять всю систему **слишком долго**.
- Автотесты позволяют **быстро находить ошибки**.

**Популярные инструменты для автоматизации:**  
✅ **Selenium** – для тестирования веб-приложений.  
✅ **Appium** – для мобильных приложений.  
✅ **JUnit, TestNG** – для бэкенд-тестирования.  
✅ **Cypress** – для фронтенда.

🎯 **Пример:**  
После изменения **формы регистрации**, можно автоматизировать проверку:

- Заполняется ли форма?
- Работает ли валидация?
- Успешно ли создается новый аккаунт?

## **Виды Regression Testing**

|**Тип**|**Описание**|**Когда применять?**|
|---|---|---|
|**Корректирующее (Corrective Regression Testing)**|Проверка системы без значительных изменений|Если код не менялся, но тесты нужно перепроверить|
|**Прогрессивное (Progressive Regression Testing)**|Тестирование при добавлении нового функционала|Когда нужно убедиться, что новый код не сломал старый|
|**Выборочное (Selective Regression Testing)**|Проверка только измененных модулей и связанных функций|Если система большая и тестировать всё дорого|
|**Полное (Complete Regression Testing)**|Полный запуск всех тестов|Перед крупными релизами или после глобальных изменений|
|**Тестирование обратной совместимости (Retest All)**|Проверка работы со старыми версиями системы|Если продукт должен поддерживать старые конфигурации|

---

## **Regression Testing vs. Retesting**

Эти термины часто путают, но у них разные задачи:

|**Критерий**|**Regression Testing**|**Retesting**|
|---|---|---|
|**Цель**|Проверить, не сломался ли старый функционал|Проверить, исправлен ли конкретный баг|
|**Когда выполняется?**|После внесения любых изменений в код|Только после исправления бага|
|**Что тестируется?**|Старые функции + новые изменения|Только конкретный фикс|
|**Требует ли баг-репорт?**|Нет|Да|

🎯 **Пример:**  
👨‍💻 **Баг:** "Кнопка 'Купить' не работает".  
✅ **Retesting:** Проверяем, исправили ли баг.  
✅ **Regression Testing:** Проверяем, что **вся система заказов работает** после исправления.

---

## **Пример сценария Regression Testing**

### **Приложение: интернет-магазин**

🎯 **Изменение:** Разработчики добавили новую **скидочную систему**.

📌 **Что проверять в регрессионном тестировании?**  
✅ Покупка товаров по обычной цене.  
✅ Применение купонов на скидку.  
✅ Оформление заказа без скидки.  
✅ Возврат товара.  
✅ Отображение скидок в корзине.

---

## **Заключение**

Regression Testing — **необходимый этап** разработки. Без него можно пропустить ошибки, которые **сломают старый функционал**, даже если новая фича работает идеально.

🚀 **Автоматизация + стратегия тестирования = качественный продукт!**
