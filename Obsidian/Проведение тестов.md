**Процесс проведения тестирования программного обеспечения** — это последовательный и систематический процесс проверки работы приложения на соответствие требованиям и выявление дефектов. Он включает несколько этапов, начиная с подготовки тестов и заканчивая анализом результатов.

---

### **Основные этапы проведения теста**

1. **Анализ требований**
    
    - Изучение документации (технических заданий, спецификаций, макетов).
    - Определение областей, которые нужно протестировать.
    - Выявление критичных частей системы (например, платежи, авторизация).
2. **Планирование тестирования**
    
    - Определение целей тестирования (функциональное, нагрузочное, регрессионное и т.д.).
    - Выбор подходов (ручное или автоматизированное тестирование).
    - Расчет необходимых ресурсов (время, инструменты, специалисты).
    - Определение критериев завершения тестирования (например, выполнение 90% тест-кейсов без критических ошибок).
3. **Подготовка тестовых данных и окружения**
    
    - Настройка тестовой среды (серверы, базы данных, виртуальные машины).
    - Создание тестовых учетных записей и данных (например, пользователи с разными ролями).
    - Подготовка необходимых инструментов (например, Postman для API, Selenium для автоматизации).
4. **Разработка тест-кейсов**
    
    - Создание четких инструкций для тестирования 
    - Определение входных данных и ожидаемых результатов.
    - Приоритизация тестов (наиболее важные тестируются в первую очередь).
5. **Выполнение тестов**
    
    - Пошаговое выполнение тест-кейсов.
    - Фиксация фактических результатов.
    - Логирование ошибок и аномалий.
    
    **Способы проведения тестирования:**
    
    - **Ручное тестирование** — тестировщик выполняет тест-кейсы вручную.
    - **Автоматизированное тестирование** — используется программный код для выполнения тестов.
    
    **Примеры тестов:**
    
    - Проверка логина и регистрации.
    - Проверка расчета скидки в корзине интернет-магазина.
    - Проверка работы приложения на разных устройствах и браузерах.
6. **Регистрация дефектов**
    
    - Фиксация ошибок в баг-трекинговой системе (JIRA, Bugzilla, Trello и т.д.).
    - Указание подробностей: шаги для воспроизведения, скриншоты, логи ошибок.
    - Определение приоритета ошибки (критическая, средняя, низкая).
7. **Анализ результатов тестирования**
    
    - Оценка успешности тестирования (сколько тестов пройдено, сколько зафейлено).
    - Составление отчета по тестированию (Test Summary Report).
    - Анализ корневых причин найденных проблем.
8. **Регрессионное тестирование**
    
    - Повторное тестирование уже исправленных или затронутых изменений.
    - Проверка, что исправления не повлияли на другие части системы.
9. **Завершение тестирования**
    
    - Проверка выполнения всех запланированных тестов.
    - Подведение итогов: что было протестировано, сколько ошибок найдено и исправлено.
    - Документирование тестового покрытия и рекомендаций для дальнейшего улучшения.

---

### **Методы проведения тестов**

1. **Функциональное тестирование:**
    
    - Проверяет, работает ли система в соответствии с требованиями.
    - Примеры: авторизация, обработка платежей.
2. **Нефункциональное тестирование:**
    
    - Изучает аспекты, не связанные с функциями системы:
        - **Производительность** — как система работает при высокой нагрузке.
        - **Безопасность** — защищенность данных и уязвимости.
        - **Юзабилити** — удобство использования приложения.
3. **Исследовательское тестирование:**
    
    - Проводится без заранее подготовленных тест-кейсов для поиска неожиданных ошибок.
4. **А/В тестирование:**
    
    - Сравнение двух версий продукта, чтобы определить, какая из них работает лучше.

---

### **Ручное vs Автоматизированное тестирование**

|Параметр|Ручное тестирование|Автоматизированное тестирование|
|---|---|---|
|Скорость выполнения|Медленное|Быстрое|
|Точность|Зависят от человеческого фактора|Исключены ошибки, связанные с невнимательностью|
|Затраты на старт|Низкие|Высокие (требуется написание скриптов)|
|Области применения|Разовые проверки, сложные сценарии|Регулярное и регрессионное тестирование|

---

### **Инструменты для проведения тестов**

1. **Для ручного тестирования:**
    
    - **TestRail** — управление тест-кейсами.
    - **JIRA** — отслеживание дефектов.
    - **Postman** — тестирование [[API]].
    - **Fiddler** — анализ сетевого трафика.
2. **Для автоматизированного тестирования:**
    
    - **Selenium** — автоматизация веб-тестов.
    - **Appium** — тестирование мобильных приложений.
    - **JMeter** — нагрузочное тестирование.
    - **Allure** — отчетность по тестам.

---

### **Ошибки, которые можно обнаружить при тестировании:**

1. Функциональные (не работает кнопка, некорректные расчеты).
2. UI/UX (неудобный интерфейс, элементы накладываются друг на друга).
3. Безопасность (уязвимости, утечки данных).
4. Сетевые (долгая загрузка, проблемы с соединением).
5. Производительность (зависания при большой нагрузке).

---

### **Критерии завершения тестирования:**
[[Цели тестирования]]
Тестирование считается завершенным, если:

- Все критические дефекты исправлены и повторно протестированы.
- Достигнуты цели тестирования, указанные в плане.
- Пройдено достаточное количество тест-кейсов (например, 95%).
- Время или бюджет на тестирование исчерпаны.
